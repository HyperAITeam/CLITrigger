# v0.2.48 — Fix runaway window-focus flicker when a popout terminal is open

Release date: 2026-08-05
Previous version: v0.2.47

## TL;DR

Fixes a severe focus flicker storm: with a terminal popped out into a separate
window, opening the new-terminal form in another project could send the two
app windows into a self-sustaining focus ping-pong (15–30Hz title-bar
flashing, effectively freezing the desktop until manual intervention). The
loop ran entirely in the Electron main process, which is why the v0.2.47
renderer-side guard did not catch it.

## Highlights

### Popout + new-terminal form no longer triggers a focus flicker storm

- Diagnosed from IME debug logs: the forced IME handoff on form entry blurs
  the main window, which hands OS activation to the open popout. Each
  window's focus-recovery bridge then re-fired the other — a stale `focus`
  event (processed after activation had already moved to the sibling window)
  turned the `webContents.focus()` rebind into an HWND activation steal,
  re-arming the sibling's bridge in an endless loop (~10,400 window events
  over 28 seconds in the captured reproduction).
- The bridge now skips rebinding on stale focus events. A fresh-focus rebind
  targets the already-active window and cannot steal activation, so the loop
  can no longer form. Lock-screen and alt-tab IME recovery paths are
  unaffected — the pending rebind still runs when focus genuinely returns.
- The main window and popout windows previously carried duplicated copies of
  the bridge; they now share a single implementation so future fixes apply to
  both.
