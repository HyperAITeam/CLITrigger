# v0.2.77 — Shared document folders, MCP SDK v2 with MCP tasks, and more MCP control

Release date: 2026-11-23
Previous version: v0.2.76

## Summary

The Documents tab can now include folders outside the project, so several projects can work from the same docs. The MCP server moves to SDK v2 and the 2026-07-28 protocol, while still serving older clients. Claude Code can now wait on a session as a background MCP task instead of re-calling the tool every 55 seconds. New MCP options let agents change project settings and pick the CLI and model for a task. Folders in the document graph can carry tags and colors.

## Highlights

### Link document folders from outside the project

- In project settings → Documents, add a folder under **Linked doc folders** with an alias. It appears in the Documents tab as `@alias`.
- Linked files can be opened, edited, created, renamed, moved, and hidden just like project files. Each folder keeps its own `.vaultignore`.
- Tags on linked files are shared: every project that links the same folder sees the same tags. Tag colors stay per project.
- Wikilinks work across the project and its linked folders, and linked docs can be injected into task prompts like any other document. The injected path is the file's real location.
- Folders must exist, be absolute, and not overlap the project folder. Moving files between the project and a linked folder isn't supported yet. Strict-sandbox agents can't edit linked folders because those folders sit outside their workspace.

### Tags and colors on document graph folders

- Right-click a folder → **Edit tags** to tag the folder itself. The folder node then takes the color of its first tag.

### MCP server on SDK v2 (protocol 2026-07-28)

- The built-in MCP server now uses MCP TypeScript SDK v2 and speaks the 2026-07-28 protocol. It still accepts the 2025 handshake, so existing registrations keep working with no changes.
- Verified with real clients: Claude Code and Antigravity connect on 2026-07-28, and Codex connects on 2025-06-18.

### `wait_session_state` runs as an MCP task in Claude Code

- When the client supports MCP tasks, `wait_session_state` returns a task right away. The server keeps waiting until the session reaches the state or ends (default 30 minutes, up to 60). Claude Code polls the task in the background and hands the result to the model, so the model calls the tool once.
- Other clients keep the previous behavior: one call waits up to 55 seconds, and the caller retries until it matches.
- Claude Code uses tasks only for calls from the main conversation of an interactive (or stream-json) session. One-shot `claude -p "…"` runs and subagent calls wait the old way. Tasks live in memory, so restarting CLITrigger drops any that are still running.

### More control from MCP

- New `update_project_settings` tool: default max turns, max concurrent tasks, default CLI, worktree use, auto-commit, npm auto-install, and the default loop rules. Loop rules merge field by field, so an agent can raise or lower `max_rounds` alone. Sandbox modes and extra CLI options are left out on purpose, so an agent can't widen its own permissions.
- `create_todo` accepts `cli_tool` and `model`. The model name goes to the CLI's `--model` as-is (for example `opus` for Claude), so there is no model list to keep current. Leave it out to use the CLI's default model. An unknown model name fails when the task runs, with the CLI's own error. Changing a task's CLI later clears its model.

## Install / Update

```bash
npm i -g clitrigger@0.2.77
```

Desktop app — pick the right asset:

- **Windows (recommended)**: `CLITrigger-Setup-0.2.77.exe` — installer with Start Menu shortcut, uninstaller, and auto-update.
- **Windows (portable)**: `CLITrigger-0.2.77.exe` — run directly, no install; no shortcuts and no auto-update (grab new versions manually).
- **macOS**: `.dmg` / **Linux**: `.AppImage`
