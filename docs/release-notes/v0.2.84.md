# v0.2.84 — Security hardening, local-only by default, no more freezes on huge doc folders

Release date: 2026-11-27
Previous version: v0.2.83

## Summary

This release closes several ways another program or web page could reach CLITrigger. The server now listens on this computer only by default, and the Cloudflare tunnel and your own browser or desktop app keep working as before. It also stops the server from freezing when a project's Documents folder is very large. Antigravity 1.5 tasks run with their prompt again, and when a CLI update breaks an option, the task log names it.

## Highlights

### Local-only by default

- Before, the server accepted connections from every network interface. On a PC with a public IP that put the login page on the internet, and Windows asked to open the firewall on first launch.
- Now only this computer and the Cloudflare tunnel can connect, and Windows no longer asks to open the firewall.
- LAN access is opt-in. See **Migration**.

### Security hardening

- **Web pages can no longer drive CLITrigger.**
  - The WebSocket origin check always runs now. Before, it only ran when `NODE_ENV=production`, which no launcher sets, so any page you visited could open the live terminal channel.
  - DNS rebinding is blocked: the server answers only to `localhost`, IP addresses, the tunnel hostname, and names in `ALLOWED_HOSTS`.
  - By default, CORS only allows the page the server itself served.
- **Account safety**
  - The first password can only be set from this computer, not over the LAN or the tunnel.
  - The login rate limit can no longer be dodged by faking `X-Forwarded-For`.
  - Logging in issues a fresh session.
  - Changing your password or logging out closes connections that were already open.
- **MCP token**
  - It is only honoured for requests made directly on this computer.
  - It is replaced when you change your password.
- **Agents can't widen their own permissions through MCP.** They can no longer create or type into raw shell sessions, or set a task's loop `check` command (it runs in a shell).
- **Startup dialogs** (folder trust, update prompts) are only auto-answered while a CLI starts up. Later output can no longer trigger them.
- **Document selection and discussion extraction** no longer run Antigravity with permission bypass, and run in an empty temp folder instead of your home folder.
- **Desktop app**
  - Crafted links such as `http://127.0.0.1:PORT@evil.example/...` no longer open as app windows.
  - The embedded web panel is locked to its own browser session.
  - Scripts no longer allow `unsafe-inline` or `unsafe-eval` in the Content Security Policy.
- **Smaller fixes**
  - URL favorites open without `cmd.exe`, so an `&` in a URL can no longer run a command.
  - Project paths with `& | < > ^ % "` are rejected, and changing a project's path is now validated.
  - Writing through a broken symlink can no longer escape the project folder.
  - The strict sandbox keeps your repo's own deny rules, and its description now says that shell commands are not isolated on Windows.
- **Dependencies:** all known vulnerabilities in production dependencies are fixed (simple-git 4, BlockNote 0.57, Express, and others).
- **Releases** now wait for a maintainer's approval before publishing.

### No more freezes on huge Documents folders

- A project rooted at a very large folder (100k+ directories) used to freeze the whole server for 15–30 seconds while it scanned for docs, including every terminal.
- Scanning now runs in the background and is cached. Re-opening the Documents tab takes milliseconds, and only changed files are read again.

### Antigravity 1.5 tasks work again

- After Antigravity 1.5 removed `--headless`, tasks failed with a help dump.
- After switching to `--print`, they ran without their prompt, because `--print` ignores stdin.
- The prompt is now passed as the `--print` argument, without going through a shell.

### Clearer failures after a CLI update

- When Claude Code, Codex or Antigravity rejects one of CLITrigger's options, the task log now says which option and which CLI version. Before, you saw "exited with code 2".

## ⚠️ Breaking Changes

- **LAN access is off by default.**
  - The server listens on `127.0.0.1` instead of `0.0.0.0`.
  - If you opened CLITrigger from another device by its IP address (`http://192.168.x.x:3000`), that stops working until you turn LAN access back on.
  - This computer and the Cloudflare tunnel are unaffected.
- **MCP agents can no longer set a loop `check` command** or create/drive raw shell sessions. Set `check` in the UI.
- **MCP clients must be re-registered after a password change.** The MCP card marks them as stale.
- **CORS:** other origins need `CORS_ORIGIN`. This only matters if you called the API from a different origin, such as a Vite dev server used without its proxy.

## Migration

To keep reaching CLITrigger from other devices on your network, turn LAN access back on and restart. With LAN access on, your password is the only thing protecting the server; for access from outside your network, use the tunnel.

- **npm CLI:** `clitrigger config lan on`. Undo with `clitrigger config lan off`.
- **Desktop app:** add `"bindHost": "0.0.0.0"` to `config.json` in the app data folder (`%APPDATA%\clitrigger` on Windows).
- **Either:** set the environment variable `BIND_HOST=0.0.0.0`. It takes precedence over the config file.

## Install / Update

```bash
npm i -g clitrigger@0.2.84
```

Desktop app — pick the right asset:

- **Windows (recommended)**: `CLITrigger-Setup-0.2.84.exe` — installer with Start Menu shortcut, uninstaller, and auto-update.
- **Windows (portable)**: `CLITrigger-0.2.84.exe` — run directly, no install; no shortcuts and no auto-update (grab new versions manually).
- **macOS**: `.dmg` / **Linux**: `.AppImage`
