# v0.2.84 — Security hardening, local-only by default, no more freezes on huge doc folders

Release date: TBD
Previous version: v0.2.83

## Summary

This release closes several ways another program or web page could reach CLITrigger, and the server now listens on this computer only by default. The Cloudflare tunnel and your own browser or desktop app keep working as before. If you reached CLITrigger from another device on your network by its IP address, see **Action required** below.

It also fixes a server freeze when a project's Documents folder is very large, and Antigravity tasks running without their prompt.

## Action required: LAN access is now off by default

Before, the server accepted connections from any network interface. On a PC with a public IP that put the login page on the internet, and Windows asked to open the firewall on first launch. Now only this computer and the Cloudflare tunnel can connect, and Windows no longer asks.

To keep using CLITrigger from other devices on your network, turn LAN access back on and restart:

- **Desktop app:** add `"bindHost": "0.0.0.0"` to `config.json` in the app's data folder (`%APPDATA%\clitrigger` on Windows).
- **npm CLI:** run `clitrigger config lan on`.
- **Either:** set the environment variable `BIND_HOST=0.0.0.0`.

With LAN access on, your password is the only thing protecting the server. For access from outside your network, use the tunnel.

## Security

- **WebSocket origin check now always runs.** It used to switch on only when `NODE_ENV=production`, which no launcher sets. Any web page you visited could open the live terminal channel. In auth-disabled (plugin) mode, that meant it could type into your shells.
- **DNS rebinding blocked.** The server answers only to `localhost`, IP addresses, the tunnel's hostname, and names in `ALLOWED_HOSTS`.
- **CORS:** only the page the server itself served is allowed by default. Use `CORS_ORIGIN` to allow others.
- **First-run password setup** is only accepted from this computer, not over the LAN or the tunnel.
- **Logins:**
  - The rate limit can no longer be bypassed by faking `X-Forwarded-For`.
  - Logging in issues a fresh session.
  - Changing your password or logging out closes WebSocket connections that were already open.
- **MCP token:**
  - It works only for requests made directly on this computer.
  - It is replaced when you change your password. Re-register MCP clients when the MCP card marks them stale.
- **Agent permissions through MCP:**
  - Agents can no longer create or type into raw shell sessions.
  - Agents can no longer set a task's loop `check` command, because it runs in a shell. Set it in the UI.
- **Auto-answering startup dialogs** (folder trust, update prompts) only happens while a CLI is starting up. Later output can no longer trigger it.
- **Document selection and discussion extraction:**
  - These one-shot calls no longer run Antigravity with `--dangerously-skip-permissions`.
  - They run in an empty temporary folder instead of your home folder.
- **Strict sandbox:**
  - It keeps your repo's own deny rules.
  - Its description now says plainly that shell commands are not isolated on Windows.
- **Desktop app:**
  - Links like `http://127.0.0.1:PORT@evil.example/...` no longer open as app windows.
  - The embedded web panel is locked to its own browser session.
- **Content Security Policy:** `unsafe-inline` and `unsafe-eval` are removed from scripts.
- **Favorites:**
  - URL favorites open without going through `cmd.exe`. Before, a URL containing `&` could run a command.
  - Project paths containing `& | < > ^ % "` are rejected.
  - Changing a project's path is now validated the same way as creating a project.
- **File writes:** writes through a broken symlink can no longer escape the project folder.
- **Dependencies:** all known vulnerabilities in production dependencies are fixed (simple-git 4, BlockNote 0.57, and others).
- **Releases:** publishing now waits for a maintainer's approval in GitHub.

## Fixes

- **Documents tab on huge folders:**
  - A project rooted at a large folder (100k+ directories) used to freeze the whole server, including every terminal, for 15–30 seconds while it scanned for docs.
  - Scanning is now non-blocking and cached. Re-opening the Documents tab takes milliseconds.
- **Antigravity 1.5 tasks:**
  - They failed with a help dump after `--headless` was removed.
  - They then ran without their prompt, because `--print` ignores stdin.
  - The prompt is now passed correctly, without going through a shell.
- **Clearer failure message after a CLI update:** when a CLI rejects one of CLITrigger's options, the task log now names the option and the CLI version. Before, it showed only "exited with code 2".
