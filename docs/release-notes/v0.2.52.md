# v0.2.52 — Korean IME input fix for the desktop terminal

Release date: 2026-09-03
Previous version: v0.2.51

## TL;DR

Hotfix for a regression introduced in v0.2.51: on the Windows desktop app, typing Korean into a terminal stalled after the first jamo — the IME kept swallowing keys but nothing was composed or sent. English input was unaffected. This release restores normal Hangul composition. No other changes.

## Highlights

### Terminal: Korean (Hangul) input works again on Windows

- **Symptom**: from the very first terminal after launch, Hangul composition opened on the first keystroke and then froze — every following key was eaten by the IME with no composition update, no commit, and nothing reaching the PTY.
- **Cause**: v0.2.51 replaced the global `transition: all` CSS rule with an explicit property list. That rule had also been applied to xterm's hidden helper `<textarea>`. The app hides xterm's inline composition preview (`.composition-view`) with `display: none`, and xterm sizes the helper textarea from that element's bounding box — so during composition the textarea collapsed to a 1×1 px, zero-line-height box. The old transition had been smoothing over that collapse by accident; once it was gone, Windows TSF stopped delivering composition updates.
- **Fix**: the composition preview is now hidden with `visibility: hidden` instead of `display: none`. It keeps its layout box (the standard xterm.js IME setup) while still never being painted, so the inline preview stays invisible exactly as before.
- Verified in Electron 43 with the IME diagnostic log: every keystroke produces a `compositionupdate` and each syllable commits with `compositionend`.
