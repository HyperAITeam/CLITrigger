# v0.2.73 — terminal sessions start sandboxed, Codex strict-mode fix

Release date: 2026-11-17
Previous version: v0.2.72

## Summary

Terminal sessions no longer always start in bypass mode. Each project now has a terminal sandbox switch, on by default: Claude Code runs in auto mode, Codex in its workspace-write sandbox with automatic review, and Antigravity asks before acting. Turn it off in Settings → Terminal to go back to bypass. This release also fixes Codex tasks failing immediately in strict mode on Codex 0.149, and SVN log view missing commits made after your last update.

## Highlights

### Terminal sandbox

- Settings → **Terminal** has a new **Terminal sandbox** card with Strict (recommended) and Permissive options. Switching to Permissive asks for confirmation first.
- In Strict mode, terminal sessions start with:
  - **Claude Code** — `--permission-mode auto`: safe actions run without asking, anything risky asks you in the terminal.
  - **Codex** — `--approve-for-me`: the workspace-write sandbox plus Codex's automatic review of approval requests.
  - **Antigravity** — no skip flag, so it asks before acting.
- Permissive works as before: every permission check is skipped.
- The setting is separate from the task sandbox in Automation Settings. Tasks keep their current behavior.
- **Behavior change:** existing projects default to Strict, so after updating, new terminal sessions start in auto/ask mode instead of bypass. Sessions that are already running keep their mode until restarted or resumed.
- `--approve-for-me` requires a recent Codex CLI (verified on 0.149). Update Codex if Strict terminal sessions fail to start.

### Fixes

- **Codex tasks in strict mode** — Codex 0.149 removed `--full-auto`, so strict-mode Codex tasks exited at once with `unexpected argument '--full-auto'`. They now use `--sandbox workspace-write`.
- **SVN log view** — "View log" in the SVN panel stopped at the working copy's last update. It now always lists from the repository's latest revision.
