# v0.2.45 — Form inputs self-heal from dead page focus (Windows IME)

Release date: 2026-08-05
Previous version: v0.2.44

## TL;DR

Fixes the Windows desktop app bug where, after interacting with a terminal, clicking into form inputs (e.g. the "New Terminal" form's title and prompt fields) did nothing — no caret, no typing, no matter how many times you clicked. Inputs now detect the dead-focus state and rebind keyboard focus on the spot.

## Highlights

### Clicking a form input now always activates it

On Windows, working inside an xterm terminal could leave Chromium's page focus dead while the OS kept routing clicks and keys to the window. In that state a click on a form input moved DOM focus but never activated the caret, and the existing recovery paths couldn't reach it: the app-level reset was a no-op on an already-focused window, the New Terminal form only ran its focus handoff once on open, and the terminal's self-heal only covered the terminal itself.

The app-level focus bridge now detects input arriving while page focus is dead (on click, key press, or focus change) and runs the proven forced rebind sequence — blur → forced IME reset → refocus the clicked target. This applies to every form input in the app (New Terminal form, Planner, settings, etc.), not just the reported one. The forced reset only fires in the dead-focus state, so healthy Korean IME composition is untouched.
