# v0.2.49 — Auto-delegated review tasks

Release date: 2026-08-21
Previous version: v0.2.48

## TL;DR

This release adds **auto-delegation**: when a task run by one CLI completes successfully, CLITrigger can automatically create a follow-up review task assigned to a different CLI (e.g. Claude writes the code, Codex reviews it). The review task chains onto the parent's branch and starts on its own. Also includes a visual tone-down pass across the task/session/schedule UI.

## Highlights

### Auto-delegated review tasks

- New per-project rule in **Settings → Execution**: enable the toggle and pick a *work* CLI and a *review* CLI (Claude / Antigravity / Codex).
- When a todo run by the work CLI finishes successfully, a review todo assigned to the review CLI is created automatically. It is chained via `depends_on`, so the existing auto-chain machinery starts it immediately and it inherits the parent's branch (the parent's worktree changes arrive squash-merged as a single commit).
- The generated review prompt asks the review CLI to diff against the project default branch, review for correctness/bugs/regressions, fix critical issues, and summarize findings.
- Guardrails: a delegated review never spawns another review (loop-safe, including `from == to`), and retry/continue completions never create duplicate review tasks.
- New `todo:created` WebSocket event — auto-created todos appear in the UI instantly, before they start running.

### UI polish

- Toned-down visual styling across status badges, todo items, session list, and schedule items — less color noise, more readable at a glance.
- Prompt inputs unified to the standard input-field style (the separate prompt-field styling was removed).
