# v0.2.64 — Task loops: auto-restart rounds until a check passes, plus web panel navigation

Release date: 2026-10-06
Previous version: v0.2.63

## Summary

Tasks can now run as a loop. Give a task a termination rule — a verification command, a done phrase, or just a round count — and the orchestrator re-runs it in the same worktree, round after round, until the rule is satisfied or a guard (max rounds, cost cap, no new commits) stops it. Loop tasks get their own "Loops" tab in the Automation hub and a project-level rule template so you don't retype the same rules. The embedded web panel gains a back button and favorites. A dock bug that duplicated minimized session chips after closing a popout window is fixed.

## Highlights

### Task loops

- **Termination rules per task.** When creating or editing a task, open the loop section and set any of: max rounds (1–50), a verification command (loop ends when it exits 0), a done phrase (loop ends when the agent prints it), per-round rules injected into every prompt, a cost cap in USD, "stop when a round makes no new commits", and whether to resume the previous session or start a fresh context each round.
- **Automatic round restart.** When a round finishes normally, the rule is evaluated. If it is not satisfied and rounds remain, the next round starts automatically in the same worktree with a follow-up prompt that states the round number and why the previous round did not pass (for example, the failing command's exit code and output tail). Costs and tokens accumulate across rounds.
- **Guards.** The loop stops and the task is marked failed when the cost cap is reached, a round leaves HEAD unchanged (with the no-changes guard on), or max rounds run out without satisfying the done rule. A loop with no done rule simply runs the configured number of rounds.
- **Round badge.** The task list and the graph detail panel show the current round over the maximum, updated live while the task runs.
- **"Loops" tab.** The Automation hub now splits loop tasks into their own tab (`?tab=loops`). The form there always shows the rule section; the regular automated-tasks tab hides it.
- **Project rule template.** Project settings has a default loop rules editor. Turning the loop on for a new task pre-fills these rules.
- **MCP.** `create_todo` accepts a `loop` parameter so agents can create looped tasks.

### Web panel: back and favorites

- A back button to the left of the address bar navigates the active tab's history and is disabled when there is nothing to go back to.
- A star toggle to the right of the address bar adds or removes the current URL as a favorite. Favorites appear as a chip bar under the address bar; click to open, hover to remove. The bar is hidden along with the address bar in collapsed fullscreen.

### Fixes

- **Duplicate minimized chips.** When a popout window belonged to a different project than the one currently open, its tab-move and close messages were dropped, leaving a stale session in the original project's saved layout. Closing the popout then resurrected it as a second minimized chip. Popout messages now carry the project id and patch the right project's saved layout, and group restore guarantees one group per session so already-corrupted layouts self-heal.

## Migration

- No action required. Two columns (`todos.loop_config`, `projects.loop_defaults`) are added automatically on the first start after updating. Existing tasks are unaffected; loop behavior applies only to tasks that have rules set.

npm i -g clitrigger@0.2.64

- **Windows (portable)**: `CLITrigger-0.2.64.exe` — run directly, no install; no shortcuts and no auto-update (grab new versions manually).
- **macOS**: `.dmg` / **Linux**: `.AppImage`
