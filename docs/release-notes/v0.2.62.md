# v0.2.62 — SVN progress banners, popout windows you can drag by the tab bar

Release date: 2026-09-15
Previous version: v0.2.61

## Summary

The SVN panel now tells you what it is doing. `svn update` streams its output live into a progress banner, so you can watch files being updated, added, deleted, or hitting conflicts instead of staring at dimmed buttons. Every other SVN command (cleanup, commit, add, revert, delete, resolve, changelists) shows a spinner banner with the command name while it runs.

Popout terminal windows holding a single stack lose their separate title bar: the tab bar is the title bar. Drag a tab or the empty strip to move the OS window, and drop it onto another window to dock the whole group at once. A coordinate bug that made cross-window docking land in the wrong zone after moving a popout is fixed.

## Highlights

### SVN: live progress for `svn update`

- The update command streams `svn update` output line by line to the browser. The banner shows how many files have been processed so far and the most recent line, so you can see each `U`/`A`/`D`/`C` as it happens.
- Previously the command buttons were only dimmed while the update ran, with nothing on screen explaining why.

### SVN: a running banner for every command

- Cleanup, commit, add, revert, delete, conflict resolution, and changelist operations now show a spinner banner labelled with the command while they run, and clear it when the command finishes or fails.
- All SVN panel commands go through a single execution path, so the banner is consistent across every button.

### Popout windows: the tab bar is the title bar

- A popout window that contains one stack no longer has a separate top bar. Minimize (Electron), redock, and close now live in the tab bar, matching the floating windows inside the app. Popouts with split groups keep the existing top bar.
- Dragging a tab or the empty part of the tab bar moves the OS window. In Electron this goes through a native window-move channel; in a browser it uses the window's own move API.
- While dragging, the popout probes other windows for docking targets. Dropping hands over every tab in the group in one step, inserted with the same rules as an in-app dock.
- Because the window being dragged covers the target window's dock indicator, the same indicator is now drawn in the source window as well, so you can see where the group will land.

### Popout windows: cross-window dock zones land where you point

- After moving a popout by its drag region, dock zone detection was offset by the distance the window had travelled, because the renderer received no mouse events during the native move. Screen coordinates are now recorded alongside each pointer sample and corrected by the page zoom factor, so docking is accurate after a move and while zoomed.
