# v0.2.56 — Web panel becomes a top-level tab with multi-tab browsing, SVN property-only changes now visible

Release date: 2026-09-04
Previous version: v0.2.55

## TL;DR

The **Web panel** moves out of the planner sidebar into its own **Web** tab in the project header, and it now supports **multiple tabs** with a Chrome-style tab strip. Links that would open a new window open as a new tab inside the panel instead of jumping to the OS browser. Dragging terminal windows over the Web panel no longer stalls. On the SVN side, items whose **properties** changed (typically an `svn:externals` revision bump) now show up in local changes and can be committed or reverted without dragging along unrelated files underneath.

## Highlights

### Web panel promoted to a top-level tab

- **New location**: the Web panel is now its own project tab, between **Automation** and **Git**, instead of a view inside the planner sidebar. The planner returns to its original layout without the web-specific height special-casing.
- **No reload on tab switch**: switching to another project tab hides the embedded page instead of tearing it down, so the guest page keeps its state when you come back.
- **Deep link**: `?tab=web` opens the project directly on the Web tab.
- Your previously saved panel URL is carried over automatically.

### Multi-tab browsing inside the Web panel

- **Tab strip**: a Chrome-style tab row with **+** (opens an empty tab and focuses the address bar) and **×** per tab. Closing the active tab selects the right-hand neighbor (or the left one at the end); closing the last tab leaves a fresh empty tab.
- **New-window links stay in the panel**: `window.open` / `target="_blank"` from the guest page used to hand off to the OS browser. They now open as a new tab in the panel. `mailto:` links still go to the OS.
- **Titles and persistence**: tab titles follow the page title, and the tab list plus the active tab are remembered per browser. The old single saved URL seeds the first tab.
- Navigating inside a tab (links, back/forward) no longer triggers a reload of the embedded page.

### Terminal window drag no longer stalls over the Web panel

- The embedded page used to swallow mouse move/release events while you dragged a floating terminal window, splitter, or tab across it, so the drag would stop or miss the release. Pointer input to the embedded page is now suspended for the duration of a host mouse press, so window moves, resizes, splitter drags, and tab tear-outs pass through cleanly.

### SVN: property-only changes (e.g. `svn:externals`) are now listed

- **Visible in local changes**: `svn:externals` is a directory property, so bumping an external's revision reports as a property-only modification. Those rows were filtered out of the local changes list. They now appear as **M** (or **C** when conflicted).
- **Commit and revert stay scoped**: because such rows are directories, a plain commit or revert would have pulled in every modified file underneath. Property-only items are detected up front and handled with an empty-depth operation, so reverting one only reverts the property, and committing one does not sweep in unlisted child files. Explicitly selected files and child items are committed as before. If detection fails, the previous behavior is used.
