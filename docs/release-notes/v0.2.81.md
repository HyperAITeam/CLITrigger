# v0.2.81 — Link doc folders from the Documents tab, reset times on the usage widget

Release date: 2026-11-24
Previous version: v0.2.80

## Summary

A small usability release. Linked doc folders now have their own section in the Documents tab, and you can link a new one from the right-click menu without opening project settings. The usage widget shows when each limit resets, so you no longer have to hover a bar to find out. The Review Queue filters now go by task status.

## Highlights

### Linked doc folders in the Documents tab

- Linked folders (`@alias`) are no longer mixed into the project's root list in the file explorer. They appear in a separate **Linked doc folders** section below it, and they no longer count toward the root's item count.
- The right-click menu has a new item, **Link external folder…**. It is available on a file or folder, on empty space, and on the header. Pick a folder and it is linked right away, with the folder name as its alias.
- If the link is rejected (the alias is already in use, or the folder overlaps the project folder), a toast shows the reason.
- Links added this way also appear under **Project settings → Linked doc folders**, where you can rename or remove them.

### Reset times on the usage widget

- Each bar now shows when its window resets, for example `resets 17:30`. Before, this was only in the tooltip.
- A window that resets more than a day from now (usually the weekly one) also shows the weekday, for example `resets Sat 09:00`.
- A window whose reset time has already passed shows 0% and no reset time, because the next reset is not known until that CLI is used again.

### Review Queue filters by status

- The filters are now **All / Done / Failed / Stopped**. They replace **Risky / Quick wins / Failed**.
- The old filters did not say what they matched, and a failed task showed up under both **Risky** and **Failed**. Each task now appears under exactly one status filter.
- **Failed** used to include stopped tasks as well. Stopped tasks now have their own filter.
