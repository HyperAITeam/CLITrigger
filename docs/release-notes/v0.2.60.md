# v0.2.60 — Ctrl+wheel zoom fixes in the desktop app

Release date: 2026-09-08
Previous version: v0.2.59

## TL;DR

A small desktop-only patch. In the Electron exe, Ctrl+wheel no longer resets the page zoom you set with Ctrl+=/- back to 100% on every tick. Ctrl+wheel now does the expected thing depending on where the pointer is: over a terminal it changes the terminal font size, anywhere else it zooms the page, and inside a web tab it zooms that web page. No changes to the server, the npm CLI, or the browser UI.

## Highlights

### Ctrl+wheel outside a terminal zooms the page instead of resetting it

- Previously, every Ctrl+wheel tick pinned the window zoom level back to 0 so the terminal could handle the gesture. If you had zoomed the app with Ctrl+=/-, one wheel tick snapped it back to 100%.
- The zoom level is no longer touched when the gesture is forwarded. With no terminal under the pointer, the tick is applied as one page-zoom step (0.5 level, the same step as the View-menu Ctrl+=/- shortcuts), clamped to roughly 48%–299%.
- Page zoom goes through the same per-host zoom store the menu roles use, so it persists across restarts like before.

### Ctrl+wheel over a terminal only affects the hovered terminal

- A terminal now bumps its font size only when the pointer is over it. The previous "focused terminal" fallback was removed, since it would otherwise fire together with the new page zoom and change both at once.
- With several terminal panes open, at most one pane changes size per tick.

### Web tabs get Ctrl+wheel zoom

- Web tab webviews now zoom on Ctrl+wheel with the same 0.5 step and clamp as the main window.
