# v0.2.60 — Resumable terminal sessions, per-session process trees

Release date: 2026-09-09
Previous version: v0.2.59

## TL;DR

Terminal sessions can now be resumed from anywhere, not just inside a worktree. Each session is pinned to its own Claude conversation id at start, so resuming reopens exactly that conversation instead of guessing at the most recent one in the folder. The resume button only appears when a saved conversation actually exists, so it no longer fails with "No conversation found".

Project settings gained a **Terminal** section that hides the Terminal tab per project and, in the same place, lists the OS processes running under each live session — the CLI plus whatever shells, hooks, and helpers it spawned. The Web tab also picks up two browser habits: middle-click closes a tab, Ctrl/Cmd+T opens one.

## Highlights

### Resume works for root sessions, not just worktree sessions

- A session now receives its own conversation id (`--session-id`) when it starts, and resuming passes `--resume <id>`. Because the id identifies the conversation directly, the working directory no longer matters — sessions running at the project root are resumable too.
- Previously resume relied on `--continue`, which picks the newest conversation in the current directory. At a project root that could easily be a todo executor's conversation, so resume was restricted to worktree sessions. That restriction now applies only to older sessions that predate the stored id.
- Sessions created before this release still resume through `--continue` inside a worktree, exactly as before.

### The resume button only shows when there is something to resume

- Claude Code writes a conversation file on the first message of a session. A session that was started and stopped without sending anything has no conversation, and resuming it used to fail with `No conversation found with session ID: …`.
- The server now checks for that saved conversation and reports a live `resumable` flag on session reads and status broadcasts. The resume button appears the moment a stopped session has a conversation, without a page refresh, and stays hidden otherwise.
- If a resume is attempted anyway, the request is refused before any process is spawned, with a message explaining that a message has to be sent in the session first. The resume checks that used to be duplicated between the route and the session manager now live in one place.

### Processes running under each terminal

- Project settings → Terminal now lists every running session with its main CLI process: name, PID, and memory. A "subprocesses" toggle per row expands what the CLI spawned to do its work — shells, hooks, status line helpers, build commands.
- Enumeration happens once when the section opens, plus whenever the refresh button is pressed. Nothing polls in the background, because a full process listing costs 1.5–2.5 seconds on Windows. Repeated requests within a few seconds share one listing.
- The Windows `cmd.exe` wrapper that hosts the CLI is folded away so the tree starts at the CLI itself.

### Per-project Terminal tab visibility

- The Terminal tab joins Web, Docs, Planner, and Git as a tab that can be switched off per project, from its own section in the project settings tab bar. Floating terminal windows that are already open keep working when the tab is hidden.

### Web tab: browser shortcuts

- Middle-clicking a tab closes it. Ctrl/Cmd+T opens a new tab and focuses the address bar. The shortcut applies while focus is on the tab strip or address bar; key presses inside an embedded page belong to that page.

## Install / Update

```bash
npm i -g clitrigger@0.2.60
```

Desktop app — pick the right asset:

- **Windows (recommended)**: `CLITrigger-Setup-0.2.60.exe` — installer with Start Menu shortcut, uninstaller, and auto-update.
- **Windows (portable)**: `CLITrigger-0.2.60.exe` — run directly, no install; no shortcuts and no auto-update (grab new versions manually).
- **macOS**: `.dmg` / **Linux**: `.AppImage`
