## 2026-11-25 — 헷갈리던 UI 정리: 리스크 점 제거, 루프 탭 통합, 끝난 세션 칩 숨김 + 모바일 스크롤·문서 폴더 연결 해제

### 배경

실제로 쓰면서 의미가 불분명하거나 필요 없어 보이는 표시가 쌓였다. 리뷰 큐 카드의 빨강·노랑 점은 무엇을 뜻하는지 알기 어려웠고, 루프는 자동 작업과 차이가 잘 보이지 않는데 탭이 따로 있었고, 아래 칩 바에는 이미 끝난 세션까지 남아 있었다. 같은 날 모바일 터미널 스크롤과 외부 문서 폴더를 지울 방법이 없던 문제도 함께 고쳤다.

### 주요 변경

#### 1. 리뷰 카드의 리스크 점 제거 (`61f9634`)

- 카드 왼쪽 위 점은 변경 줄 수(실패 또는 300줄 초과 = 빨강, 50줄 이상 = 노랑)만으로 매긴 등급이라 실제 위험도와 맞지 않았다.
- **서버**: `classifyRisk`와 응답의 `risk` 필드 제거. **클라이언트**: 점과 `ReviewItem.risk`, `review.risk.*` 번역 키 제거.

#### 2. 루프 서브탭을 자동 작업 탭으로 다시 합침 (`2c5d312`)

- 루프는 자동 작업에 "검증 통과까지 다시 돌리기"를 붙인 옵션인데 별도 탭이라 둘의 차이가 헷갈렸다. GFRenderSRP의 루프 작업 73개는 모두 1라운드에서 끝나(에이전트가 스스로 검증하고 끝냄) 반복이 한 번도 일어나지 않았다.
- **클라이언트**: 자동화 허브 탭은 자동 작업 · 토론 · 루틴 · 통계. 자동 작업 탭이 모든 TODO를 보여주고, 폼의 "종료 규칙이 만족될 때까지 반복 (루프)" 체크박스로 루프를 켠다(라운드 배지 유지). `loopMode` prop 체인과 루프 탭 전용 번역 키 제거, 예전 `?tab=loops` 링크는 자동 작업 탭으로 연다.
- MCP(`create_todo`의 `loop`, `delegate` 프롬프트)는 루프를 작업 옵션으로만 다뤄 변경 없음.

#### 3. 아래 칩 바에서 실행 중이 아닌 세션 숨기기 (`bc36312`)

- **클라이언트**: `GlobalSessionDockTray`가 칩의 세션 상태를 `GET /api/sessions/:id`로 한 번 받고 WS `session:status-changed`로 갱신한다. 칩의 세션이 모두 `running`이 아니면(대기·완료·실패·중지) 칩을 숨긴다.
- 창 배치는 localStorage에 그대로 남아 세션을 다시 시작하면 칩이 돌아온다. 별도 창(popout) 칩은 살아 있는 OS 창으로 돌아갈 유일한 핸들이라 유지.

#### 4. 모바일에서 손가락으로 스크롤백 보기 (`57cbc2a`)

- 모바일 한글 입력용 투명 textarea가 터미널 전체를 덮어 터치 드래그가 xterm 뷰포트에 닿지 않았다.
- **클라이언트**: 오버레이의 `touchmove`를 줄 단위로 환산해 `term.scrollLines()`로 넘긴다. 스크롤백이 없을 때(`baseY === 0`)는 페이지 스크롤을 막지 않는다.

#### 5. 연결된 문서 폴더 '연결 해제'와 사라진 폴더 표시 (`6c04810`)

- **클라이언트**: 파일 탭의 `@별칭` 폴더 우클릭 → **연결 해제**로 `vault_links`에서 뺀다(폴더 파일은 그대로).
- 서버가 stat하지 못한 연결 폴더(`mtime: null`)는 취소선 + 경고 아이콘 + "폴더를 찾을 수 없음" 툴팁으로 표시.
- **i18n**: `files.unlinkFolder`, `files.linkMissing` ko/en.

### 아키텍처 결정

1. **사라진 연결 폴더는 자동 삭제하지 않음**: 서버는 폴더가 지워졌는지 외장 드라이브가 빠졌는지 구분하지 못한다(둘 다 `mtime: null`). 자동 삭제하면 드라이브를 잠깐 뺐을 때 연결이 사라지므로, 표시만 하고 해제는 사용자가 한다.
2. **끝난 세션 칩은 닫지 않고 숨김**: 창 배치(분할·탭 묶음)를 지우지 않아야 세션을 다시 시작했을 때 원래 자리로 돌아온다. 상태를 모르는 동안(조회 전·실패)은 칩을 보여준다.
3. **모바일 스크롤은 `term.scrollLines()` 직접 호출**: 모바일 입력 경로는 `term.onData`를 PTY로 보내지 않아, 합성 wheel 이벤트로 xterm이 만들어 내는 키 시퀀스는 버려진다. 그래서 일반 버퍼 스크롤백만 지원하고, 스크롤백이 없는 전체 화면 TUI(alt screen)는 범위 밖.
4. **루프 기능은 유지, 탭만 제거**: 에이전트가 검증을 건너뛰고 끝내는 경우를 잡는 안전장치라 기능은 남겼다.
