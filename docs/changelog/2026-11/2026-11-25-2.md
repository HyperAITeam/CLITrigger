## 2026-11-25 — 통계 바로잡기: CLI 'Unknown' 집계, 캐시 토큰 누락, 고장 난 초기화

### 배경

자동화 → 통계 화면에서 작업 대부분이 CLI 'Unknown'으로 잡히고, 총 토큰(450만)이 비용($366)에 비해 지나치게 작았다. 확인해 보니 집계 쿼리와 토큰 합산 방식에 여러 문제가 겹쳐 있었고, 초기화 버튼도 같은 날 만든 작업을 숨기지 못하고 있었다.

### 주요 변경

#### 1. 통계 쿼리 바로잡기 (`3594d49`)

- **CLI 도구별**: 작업에 `cli_tool`이 없으면(프로젝트 기본 CLI로 실행) `unknown`으로 묶던 것을 리뷰 요약과 같은 `COALESCE(t.cli_tool, p.cli_tool, 'claude')`로 귀속. GFRenderSRP 기준 Unknown 114개가 Claude로 합쳐진다.
- **초기화·기간 필터**: `created_at`은 ISO(`…T…Z`)인데 초기화 기준(`datetime('now')`, `… …`)과 기간 필터를 문자열로 비교해, `T`가 공백보다 커서 같은 날 만든 작업은 초기화 뒤에도 집계되고 7/30/90일 경계가 하루 어긋났다. `datetime(t.created_at)`으로 비교한다.
- **일별 차트**: UTC 날짜 대신 서버 로컬 날짜(`date(t.created_at, 'localtime')`)로 묶는다. 한국 시간 오전 9시 전에 만든 작업이 전날로 잡히던 문제.
- **i18n**: 일별 비용 차트 토글에 `analytics.cost`/`analytics.tokens` 키가 그대로 보이던 문제 (키 추가).
- **테스트**: 앱과 같은 ISO `created_at`으로 초기화 테스트를 바꾸고, 기본 CLI 귀속 테스트 추가. 두 테스트 모두 수정 전 코드에서 실패함을 확인.

#### 2. 총 토큰에 캐시 토큰 포함, Continue 라운드 비용 누적 (`3af225d`)

- **서버**: `todos.total_tokens`가 input + output만 세서 Claude 실행의 대부분인 캐시 읽기·쓰기 토큰이 빠졌다(GFRenderSRP: 450만 대 실제 약 5.9억). `taskUsageTotals()`가 캐시 토큰까지 더한다.
- **서버**: 비용·토큰 누적 기준을 "루프 작업이면"에서 "2라운드 이상이면"으로 바꿨다. Continue 라운드가 이전 라운드 비용을 덮어쓰지 않고, 실패한 루프 라운드도 누적하며, Retry 뒤 1라운드는 새로 센다.
- **DB**: 저장된 `token_usage` JSON으로 기존 행의 `total_tokens`를 한 번 다시 계산하는 마이그레이션(`migration.total_tokens_with_cache` 플래그). 여러 라운드를 누적한 행은 마지막 라운드 값만 남아 있어 건드리지 않는다.
- **테스트**: `task-usage-totals.test.ts` (1라운드 교체, 이후 라운드 누적).

### 아키텍처 결정

1. **비용 숫자는 그대로 둔다**: 비용은 Claude Code `result` 이벤트의 `total_cost_usd`(API 정가 기준 추정치)이고 집계는 맞았다. 구독 요금제의 실제 청구액과 다르다는 점은 위키 통계 섹션에 적었다. Codex·Antigravity·대화형 실행은 사용량을 보고하지 않아 $0으로 잡힌다.
2. **토큰 정의를 비용과 맞춤**: 비용은 캐시 토큰까지 포함해 매겨지므로 토큰도 캐시를 포함해야 두 숫자가 같은 실행을 설명한다.
3. **CLI 귀속은 현재 프로젝트 기본값 기준**: 실행 당시의 CLI를 따로 저장하지 않으므로, 나중에 기본 CLI를 바꾸면 예전 작업도 새 기본값으로 묶인다. 리뷰 요약과 같은 규칙을 쓴다.
