## 2026-11-12 — MCP handoff 프롬프트: 대화 맥락을 새 세션으로 넘기기

### 배경

긴 대화를 이어가다 맥락이 무거워지면 새 세션에서 이어서 작업하고 싶은데, 지금까지는 사용자가 직접 요약을 써서 새 세션에 붙여넣어야 했다. Claude Code 자체의 세션 간 메시지 기능은 Claude 전용이라, Claude/Codex/Antigravity를 모두 다루는 CLITrigger에서는 기존 세션 인프라 위에 넘기기 기능을 둔다.

### 주요 변경

#### 1. MCP `handoff` 프롬프트 + 세션 생성 브로드캐스트 (`31dbe40`)

- **서버(MCP)**: `registerPrompt('handoff')` 추가. 선택 인자 `instruction`(새 세션이 할 일). 프롬프트가 에이전트에게 `list_projects`로 현재 디렉터리의 프로젝트 찾기 → 목표·한 일·남은 일·결정·주의점 요약 → `create_session(description=요약)` 순서를 지시하고, `start_session`/`send_session_input`은 호출하지 않게 한다. Claude Code에서는 `/mcp__clitrigger__handoff`로 노출.
- **서버(MCP)**: `create_session` 도구 설명에 description이 첫 프롬프트로 보류된다는 동작과 "에이전트가 직접 구동할 세션은 description 없이 만들 것"을 명시.
- **서버**: `POST /api/projects/:id/sessions`가 WS `session:created`(세션 전체 row)를 브로드캐스트. MCP 등 UI 밖에서 만든 세션이 새로고침 없이 목록에 나타난다.
- **클라이언트**: `ProjectDetail`이 `session:created`를 받아 현재 프로젝트 세션이면 목록 맨 앞에 추가. 직접 생성 시 HTTP 응답과 브로드캐스트가 둘 다 오므로 `handleAddSession`과 WS 핸들러 모두 id로 중복을 막는다.
- **테스트**: MCP 테스트에 프롬프트 목록·`instruction` 반영 검증 추가.

### 아키텍처 결정

1. **스킬 파일 대신 MCP 프롬프트**: SKILL.md는 CLI별 스킬 폴더에 설치하는 단계가 필요하지만, MCP 프롬프트는 `clitrigger` MCP를 연결한 곳이면 바로 쓸 수 있다. Codex·Antigravity의 MCP 프롬프트 지원 여부는 미확인 — 지원하지 않으면 자연어 요청으로 같은 도구를 쓴다.
2. **기존 Send/Skip 보류 경로 재사용**: 요약을 `send_session_input`으로 PTY에 직접 치지 않고 세션 description으로 넣는다. 위키 주입에서 이미 검증된 여러 줄 첫 프롬프트 전달 경로를 그대로 쓰고, 사용자가 요약을 미리 보고 보내거나 버릴 수 있다. 새 서버 상태도 없다.
3. **세션 목록/환경변수 도구는 보류**: 새 세션으로 넘길 때는 대상 세션을 찾을 필요가 없고, 프로젝트는 현재 디렉터리와 `project.path` 비교로 찾는다(워크트리는 `<path>/.worktrees/` 아래). 이미 열린 세션으로 넘기는 기능이 필요해지면 `list_sessions`와 `CLITRIGGER_*` 환경변수 주입을 추가한다.

### 알려진 제약

- description이 있는 세션을 MCP `start_session`으로 시작하면 UI에 Send/Skip 배너가 뜨지 않고(배너는 UI가 직접 시작했을 때의 응답으로만 표시) 보류 중이라 터미널 입력도 막힌다. `handoff`는 세션을 직접 시작하지 않아 이 경로를 피한다.
